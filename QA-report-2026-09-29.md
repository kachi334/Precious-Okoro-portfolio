# QA Report — Precious Okoro Portfolio Site
**Date:** 2026-09-29
**Scope:** index.html, about.html, work.html, experience.html, contact.html, assets/style.css, assets/main.js (case study pages moniger.html/fasttrackux.html/beacon.html checked only for link integrity, not full content)
**Tracks:** Code QA + Content QA

## 🔴 Critical Issues

### 1. Two different jobs share identical dates on experience.html
`experience.html:85` (Moniger) and `experience.html:103` (Babelos) both read **"Jan 2022 – Feb 2026"** — same start month, same end month, same year span, for two separate full-time-sounding roles. This page exists specifically for recruiters/hiring managers scanning a timeline; identical overlapping dates on two different jobs reads as a copy-paste error and undercuts the "track record" the page is trying to establish. The same Moniger date range is also echoed in the index.html teaser (`index.html:339`), so this isn't a one-off typo — it'll need fixing in both places once you confirm the real Babelos dates.

**Fix:** Confirm Babelos's actual start/end dates (were the two roles genuinely concurrent — moonlighting alongside Moniger? If so, say so explicitly, e.g. add "(concurrent)" — otherwise correct the range).

## 🟡 Improvements

### 2. Four of eight pages have no `<h1>`
`about.html`, `contact.html`, `experience.html`, and `work.html` all open straight into an `<h2>` with no `<h1>` anywhere on the page (confirmed via grep — 0 matches on all four). `index.html`, `moniger.html`, `fasttrackux.html`, and `beacon.html` each have exactly one `<h1>`. Every page should have one `<h1>` naming its main content, even if it's styled identically to the other headings — screen readers and SEO both rely on it, and right now half the site skips the level entirely.

**Fix:** Change the top-level heading on each of the four pages from `<h2>` to `<h1>` (no visual change needed — restyle via CSS selector if the class currently implies "h2 size").

### 3. Inconsistent testimonial attribution for the same client
The Oduko testimonial appears on both `index.html:364` and `contact.html:145`, attributed differently:
- index.html: **"Chioma"**, *CEO at Oduko*
- contact.html: **"Chioma Chinwuko"**, *CEO/Founder at Oduko*

Different quote text on each page is fine (two snippets from the same client), but the name and title should match everywhere she's cited.

**Fix:** Pick one full name and one title ("Chioma Chinwuko, CEO/Founder at Oduko" reads more credible) and use it on both pages.

### 4. About-teaser copy on index.html has drifted from about.html's actual bio
The inline comment at `index.html:207` says the teaser is a "condensed intro only" of the full bio on about.html, but the wording has diverged in substance, not just length:
- about.html: "...helping B2B SaaS, fintech, edtech, and **enterprise technology teams**..."
- index.html: "...I've built and scaled content systems for B2B SaaS, fintech, edtech, and **AI products**..."

Not wrong, but if a visitor reads the teaser then clicks through to About, the audience list changes, which slightly undercuts the "condensed version of the same thing" framing.

**Fix:** Either align the audience list, or reword the comment so it's clear the teaser is intentionally a distinct opening line rather than a trim of the same paragraph.

### 5. Missing role/company context for one testimonial
`contact.html:153` — Lahek Gupta's testimonial has no title, just "· FastTrackUX," while the other two testimonials on the same page include a role ("CEO/Founder at Oduko," "CEO at Aliena LLC"). Reads as unfinished next to the other two cards.

**Fix:** Add a role (e.g., "Product Lead" / whatever's accurate) or drop to a consistent "· FastTrackUX" format for all three if no title is available.

## 🟢 Suggestions

### 6. `.image-block-label` placeholder pattern is solid, worth double-checking on future additions
The "Add headshot" placeholder label on the avatar block (`index.html:213`) is correctly hidden via `.about-head .avatar-block .image-block-label { display: none; }` (style.css:680), and `precious-headshot.jpg` does exist in `images/`, so nothing is currently broken. Flagging only because this pattern (visible placeholder text hidden by a scoped CSS override) is easy to accidentally leave exposed if a new image block is added elsewhere without the matching override — worth a quick visual check anytime a new `.image-block` is added.

### 7. Dark-mode / contrast engineering already looks solid
Spot-checked `style.css` for the two gotchas flagged in past sessions (opacity-based text hierarchy, hardcoded shadow `rgba()` breaking in dark theme) — both are already handled deliberately: text-safe color variants are documented inline with contrast ratios (e.g. `--ink-faint` comment noting the old value "failed WCAG AA (3.44:1)"), and `.dark-block`/`.violet-block`/`.mint-block`/`.client-deck` explicitly re-pin their tokens back to light-mode values under `:root[data-theme="dark"]` so fixed-contrast "punctuation" sections never invert unexpectedly. No action needed — noting it held up under review.

### 8. No `<h1>`-adjacent nav "Home" state
index.html's nav never marks any link `active` (the wordmark serves as the implicit home link, and there's no separate "Home" nav item), while every other page marks its own link active. This is consistent with the design, not a bug — just confirming it's intentional rather than a missed active-state.
